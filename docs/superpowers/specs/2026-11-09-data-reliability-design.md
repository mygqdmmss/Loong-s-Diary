# 日记关键词与备份可靠性

用户要求继续处理开发现状清单的第 1、2 项：自动关键词提取，以及备份恢复的数据安全。

## 范围与设计

- 使用现有 Flutter、Isar、Jieba 和 Rust Bridge，不更换数据库或备份格式，不增加依赖。
- 等待完整 Rust 初始化；保存日记时恢复分词与 TF-IDF 前 5 个关键词。只有完整分析成功才更新两个派生字段；失败保留已有值并继续保存正文。空正文成功清空派生字段。
- 备份解压到应用数据目录中的独立临时目录。先检查 ZIP 条目路径、重复名称、数据库条目、文件长度和 CRC，再打开数据库读取并校验数据。
- 当前备份采用 Zstd，现有 Dart archive 不支持该算法；复用现有 Rust ZIP 解压接口，不修改生成绑定或预编译库。
- 所有校验成功后，旧媒体目录移动到回滚目录，暂存媒体移动到正式目录，数据库最后在一个 Isar 事务中替换。事务或移动失败时恢复旧媒体。提交后的清理失败不冒充导入失败。
- 保持原有全量导入语义、搜索行为、手工标签、UI 和数据模型。

## 方案取舍

恢复旧的两行 Rust 调用最小，但未处理初始化和异常；因此采用共享初始化与独立分析函数。备份仅提前解压仍不能处理替换途中的失败，因此采用暂存、回滚目录和数据库原子事务。引入新数据库、压缩依赖或改变文件格式不在本次范围。

## 验证

使用合成日记和临时目录，禁止读取或恢复用户真实日记。回归覆盖提取失败保留旧值、空文本、成功排序、初始化等待；备份覆盖损坏 ZIP、路径越界、重复条目、CRC 错误、数据库失败、替换回滚和成功恢复。运行全部 Flutter 测试，并对变更文件做静态分析。原生平台构建受本机工具链限制时如实报告。

## 实施选择

以上实现细节由助手依据用户授权和现有代码确定。修复在独立的 codex/diary-data-reliability 分支完成，不进行远端推送或安装到用户设备。
